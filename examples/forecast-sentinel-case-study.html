03 · How it works

Facts, judgement, then controlled action

The architecture draws a hard line between reproducible detection and contextual judgement. This is the project’s load-bearing decision—and its safety boundary.

Python · deterministic

What changed?

Code walks bounded lineage, captures schemas, and calculates the diff. The same inputs always produce the same drift facts.

  • get_lineage
  • list_schema_fields
  • Recorded baseline + typed diff
The model never detects drift.
Gemini · read only

Does it matter?

The agent verifies paths, reads field meaning, weighs model consequence, and emits one typed verdict.

  • get_lineage_paths_between
  • get_dataset_queries
  • emit_verdict
The model never receives mutation tools.
Python · orchestrator

What happens next?

Only after a valid verdict does code perform independently fallible catalog mutations exactly once.

  • Clear obsolete status tags
  • Add current status
  • Append status + save report
Humans remain accountable for remediation.

Write-back result · 4 of 4 succeeded

  • ✓remove_tagsCleared obsolete Sentinel status tags
  • ✓add_tagsAdded model-invalidated
  • ✓update_descriptionAppended the timestamped verdict
  • ✓save_documentSaved linked Analysis findings

Why write-back is the differentiator

A lineage diagram explains dependency. A catalog mutation changes the next person’s decision.

The model page itself now carries the invalidation tag, appended status, and linked analysis—without granting the model permission to write anything.
